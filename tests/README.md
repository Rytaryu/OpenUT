# M1 の要件とテスト

保存したログの再生テストは `cargo test --test replay` で実行します。すべての PR では `bash .github/scripts/verify.sh` で実行します。

## 再生ケース

`tests/replay/<ケース名>/` に `ViveTrackerServer_YYYYMMDD.txt` を 1 つ以上と、`expect.toml` を置きます。`ViveTrackerDriver_YYYYMMDD.txt` も入力に含められます。同じ種類のログはファイル名の日付順に読み、各ファイル内は記録順に読みます。ケース名のハイフンをアンダースコアにした名前のテストを `tests/replay.rs` に追加します。

| ケース | 確認すること |
|---|---|
| `synthetic-r1-second-host-command` | ホストへの 2 度目の命令の後に Wi-Fi の問い合わせが続く。R1 をホストについて 1 回検出する |
| `synthetic-normal-start` | ホストからクライアントへ Wi-Fi 情報が渡り、地図の同期と位置合わせが終わる。検出は 0 回 |
| `synthetic-utf16` | ふつうの開始のケースを UTF-16LE（BOM つき、CRLF）にしたもの。記録数、見出しと設定の数、検出結果が元のケースと一致する |
| `hub-2026-11-23-28` | 匿名化したサーバーとドライバーの 6 日分。全 91,356 件、うち見出し・設定 317 件、先頭を読めなかった記録 0 件。R1 の比較は M1-13 の後半で追加する |

3 ケースの合成ログは、VIVE Hub の[ログの見本](../docs/research/hub-log-samples.md)に合わせています。解読と先頭の解析では、14 行の見出し・設定と、先頭を読めなかった記録が 0 件であることを確かめます。検出を比較するテストは M1-6 で有効にします。実物のログを追加する場合は、L-1 の匿名化を通したものを使います。

日次集計は、`expect.toml` の `[summary."2026-11-28"]` の下に比較する項目だけを書きます。集計の JSON が配列を含むときは、位置を 0 から数えます。たとえば `"trackers.0.tracking_s" = 1530.0` は、`trackers` 配列の先頭の追跡時間を比べます。

## 要件との対応

要件と受け入れの基準は [PRD の 5 章](../docs/product/PRD.md#5-m1-見張り役)、テストの順序は [実装計画](../docs/design/implementation-plan.md) に従います。

| 要件・受け入れの基準 | 確かめ方 | テストの場所 |
|---|---|---|
| W-1 UTF-16 のログを追記分だけ読み、0 時に切り替える | 見本の行の解読と解析。サーバーとドライバーの見出し、ドライバーの本文内の LF を含む再生。追記と切り替え。VIVE Hub が書いている間に読めるか実機で確認 | `tests/replay.rs` の `synthetic_utf16` と `crates/openut-hublog/src/replay.rs` の単体テスト。M1-1、M1-3、M1-4。実機は設計 14 章の U-13 |
| W-2 トラッカーごとの状態と PC 側の Wi-Fi 情報を保つ | 単体テストで状態遷移表の各行を確かめる | M1-5 |
| W-3 Wi-Fi 情報なしを検出し、対象の電源入れ直しを案内する | 単体テストで R1 と案内の対象・文言を確かめる。合成ログと匿名化ログの再生。オーナーの実機で電源入れ直しの効果を確認 | M1-6、M1-7、M1-13。`tests/replay.rs` の `synthetic_r1_second_host_command_detections` と `synthetic_normal_start_detections`（M1-6 で有効化）。実機は設計 14 章 |
| W-4 地図同期の遅れ、ホストの位置合わせ、操作と関係のない切断を検出し案内する | 見本に沿うサーバーとドライバーの行を解読・解析し、R2、R3、R4 の条件と境目を再生で確かめる。R4 ではドライバーの電源オフ予告を使う | ドライバーの読み取りは `crates/openut-hublog/src/replay.rs`。M1-3 の出来事の変換、M1-6 の `synthetic-r4-power-off`、M1-7 |
| W-5 デスクトップと SteamVR に案内し、繰り返しを抑える | 単体テストで配信、間隔とまとめを確かめる。オーナーの実機で両方の表示を確認 | M1-7、M1-10、M1-11、M1-12 |
| W-6 日ごとの集計をファイルに残す | 単体テストと合成ログの再生で、日付の切り替えと集計値、ファイル出力を確かめる | M1-8、M1-9 |
| W-7 実機に命令を送らない | 依存と入出力をレビューし、ログの読み取り専用オープンを単体テストで確かめる | 全項目のレビュー、M1-4・M1-9 のログ読み取り |
| W-8 保存したログを時刻順に流して検出を確かめる | 比較の単体テストと、合成・匿名化ログの再生テストを CI で実行する | `src/replay.rs` の単体テスト、`tests/replay.rs` の再生ケース、M1-6、M1-13 |
| W-9 ログの場所、台数、シリアル番号を固定しない | 単体テストで設定と自動検出、合成ログで台数と識別子を変えて確かめる | M1-5、M1-9 |
| 受け入れ：2026-11-23〜28 のログで W-3 が 4 回だけ | 匿名化ログの再生で 11/26 01:43、11/27 22:53・22:56・22:59 の検出だけがあることを確かめる | `tests/replay/hub-2026-11-23-28/`。検出の比較は M1-13 の後半で追加する |
| 受け入れ：VR の動作を重くしない | オーナーの実機で VIVE Hub と SteamVR を動かし、OpenUT の使用前後のフレーム時間と、使用中の CPU・メモリを確認 | M1-9〜M1-12。実機は設計 12 章 |
| 受け入れ：想定と違う行があっても読み続ける | 単体テストで乱れたバイト列、知らない行、壊れた数値と、その次の行の扱いを確かめる | M1-1、M1-3 |
