# M1 見張り役の画面と通知の見た目

M1（見張り役）の、トレイのアイコン、状態の窓、SteamVR の中の案内の板、デスクトップのトースト、文言の見た目を決める。最終更新: 2026-11-28（第 3 版）。

第 3 版は、オーナーの返事（Issue #23）を受けて全体を作り直した。

- 状態の窓を横長にした。トラッカーを 1 台ずつタイルにして横に並べ、VIVE Hub のように、機器が並んだ画面にした。縦長の窓はやめた（横長の窓だけにする）。
- 表示はいつも暗い表示にした。VR の板と同じ色の組で、SteamVR と並べて使う画面になじむようにした。
- 文言を、yomiyasu（nanaism/yomiyasu）の決まりで直した。「トラッカーが始まりません」のような不自然な言い方をやめた（6.5 に、変えたところを並べた）。
- PR #21 の 2 回目のレビューの指摘に合わせて、表示名を、文字の数ではなく描いた幅で縮め、番号に置き換えたあとも必ずほかと違う名前になる手順にした（6.4）。

根拠と範囲:

- 根拠: `docs/design/m1-watcher.md` の 7 章（何をいつ見せるか、文言の意味、操作の流れ、使う部品）、`docs/product/PRD.md` の W-5・W-6、`docs/project/roles/ux.md` のオーナーの方針、Issue #23 のオーナーの返事。
- **何をいつ見せるかは、設計（`m1-watcher.md` の 7.1〜7.4）のまま変えていない。** この文書が決めるのは、配置、寸法、色、書体、状態ごとの違い、文言の言い回し。設計に書かれていなかったために決めたことは、9 章に並べた。
- 画面の部品は設計のとおり（状態の窓は `eframe`／`egui`、トレイは `tray-icon`、トーストは `tauri-winrt-notification`、VR の中は OpenVR のオーバーレイに自前で描いた画像）。この文書の値は、どれもこの部品で作れる。

## 1. 共通の決まり

目立たせるのは、トラッカーのタイルに並べた段階の枠（3.3）だけにする。トラッカーは、接続済み → Wi-Fi 待ち → 地図を同期中 → 位置合わせ中 → 追跡中 の順に進む。タイルの中に下から上へ 5 つの枠を置き、通った段階を塗り、いまの段階に経過時間を入れる。段階の名前は左の列に 1 回だけ書き、どのタイルでも同じ高さの行にそろえる。「追跡が始まらない」不具合のときは、何台かのいまの枠が「Wi-Fi待ち」の行に横一列に並んで見える。ほかの部分は控えめにする。

### 1.1 書体

- Yu Gothic UI だけを使う（オーナーの方針: 書体は 1 系統）。太さは Regular と Bold の 2 つだけ。
- 実行時に Windows の書体のフォルダー（`%WINDIR%\Fonts`）から読む（配布物に入れない。設計の 7.2）。ファイルは `YuGothR.ttc`（Regular）と `YuGothB.ttc`（Bold）。TTC の中の書体は、番号を決め打ちせず、名前（family が `Yu Gothic UI`）で選ぶ。
- なければ、設計（7.2）の順に Meiryo UI（`meiryo.ttc`、Bold は `meiryob.ttc`）、MS ゴシック（`msgothic.ttc`。Bold はないので Regular で代える。太字の作りものはしない）。
- 大きさは、デスクトップが 13・14・16 px（Windows の拡大率 100% での論理の画素）、VR の板が 54・64 px（テクスチャーの画素）の 5 つだけ。

| 使う場所 | 大きさ | 太さ |
|---|---|---|
| 監視の状態、案内の見出し | 16 | Bold |
| タイルの名前、ボタン、ラベルと組になった値 | 14 | Bold |
| 案内のすること、今日の値、チェックボックスの名前、入力欄の文字 | 14 | Regular |
| 段階と集計の名前（左の列）、ラベル、ログの日付、監視の状態の 2 行目 | 13 | Regular |
| ホストのタグ、いまの枠の経過時間、「今日」 | 13 | Bold |
| VR の見出し | 64 | Bold |
| VR のすること | 54 | Regular |

ファイル名は、Windows 10・11 の日本語版で一般的なもの。日本語以外の Windows にあるかは確かめていない（設計の 14 章と同じ）。M1-11 の試作で確かめる。

### 1.3 文言の書き方

オーナーの方針（`roles/ux.md`）のとおり、残す文字は、いま何をすればよいかの 1 行、状態、数、押せる物の名前だけにする。説明の文と、小さい補足の文字は置かない。文言は yomiyasu の決まり（意味を変えない、直訳語を使わない、助詞を落として漢語を詰めない）で読み直した（6.5）。

- 全角と半角のあいだに空白を入れない（例: `Wi-Fi待ち`、`トラッカー3`）。数と単位も詰める（`4分`、`3回`、`1件`）。
- 見出しは「です・ます」で、状態を言い切る。すること（1 行）は、利用者に頼む「〜してください」にする。第 2 版の言い切りの形（「入れ直す」）は、見出しの「です・ます」と混ざって読みにくかったのでやめた。
- 「。」のあとは、どの画面でも改行する。「〜入れ直してください。」と「ほかのトラッカーと〜」を別の行にする。
- 折り返すのは、6 章の表で「／」を入れた場所だけにする。文節の切れ目のうち、切っても読みやすい所だけに「／」を入れた（「そのままに／してください」のように、動詞と「ください」のあいだでは切らない）。文言の関数（`openut_core::text`。設計の 3.6）は、文字列ではなく「行ごとの、切ってよい場所で分けた語句の並び」を返し、窓と VR の板は 4.4 の手順で折り返す。トーストは Windows が折り返すので、5 章の工夫だけをする。
- トラッカーの名前（`{T}`、`{H}`）は、6.4 の表示名にしてから入れ、1 つの語句として扱う。

### 1.4 マーク（OpenUT のマーク）

輪と中心の点の形。トラッカーのカメラと、見守る目を兼ねる。トレイ、状態の窓、窓のアイコン、VR の板、トーストのロゴで、同じ形を使う。

| 形 | 使う場所 |
|---|---|
| 輪 ＋ 点（ふつう） | トレイと状態の窓のふつうの見え方、窓のアイコン、VR の板とトーストのロゴ（色で案内と直ったを分ける） |
| 輪 ＋ 点 ＋ 右上の点（案内あり） | トレイと状態の窓の、案内があるとき |
| 輪 ＋ 斜めの線（見えていない） | トレイと状態の窓の、ログが見えていないとき |

描き方は 2.2。画像のファイルを読まずに、どの大きさでもコードで描ける形にした。

## 2. トレイのアイコン

### 2.1 3 つの見え方

| 見え方 | 条件（設計の 7.4） | マーク | 指を置いたときの 1 行 |
|---|---|---|---|
| ふつう | 監視中・待機中で、案内の欄が空 | 輪 ＋ 点、`icon_normal` | 監視中: `OpenUT 追跡中 {a}/{b}台`（a は追跡中の台数、b は未接続以外の台数）。待機中: `OpenUT 待機中` |
| 案内あり | 案内の欄に 1 件以上 | 輪 ＋ 点（`icon_normal`）＋ 右上の点（`icon_badge`） | `OpenUT 案内{n}件` |
| 見えていない | ログが見つからない・読めない・更新されていない | 輪 ＋ 斜めの線、`icon_blind` | `OpenUT ログが見つかりません`、`OpenUT ログを読めません`、`OpenUT ログが{m}分更新されていません` |

- 見え方が重なったときは、見えていない ＞ 案内あり ＞ ふつう の順で決める（ログが更新されていなければ、欄の案内は古い見込みが高いため。設計に書かれていないので、9 章で PM に確かめる）。
- 色だけでなく形（右上の点、斜めの線）でも見分けられるようにした（色を見分けにくい人のため）。
- 「ログの形が想定と違う」ときは、設計どおり監視中のまま（ふつうか案内あり）。
- メニュー（右クリック）: `開く`、区切り、`終了`。左クリックでも状態の窓を開く（設計の 7.4）。

### 2.2 マークの描き方（どの大きさでも同じ手順）

大きさ S 画素の正方形に、画素ごとの「覆う割合」を計算して描く（輪郭をなめらかにするため）。画素 (x, y) の中心は (x + 0.5, y + 0.5)。中心 c = (0.5S, 0.5S)。d を「形のふちまでの距離（画素。内側が負）」とすると、覆う割合は clamp(0.5 − d, 0, 1)。

| 部品 | 形（S に対する割合） | d |
|---|---|---|
| 輪 | 中心線の半径 0.34S、太さ 0.16S | \|r − 0.34S\| − 0.08S（r は c からの距離） |
| 点 | 半径 0.13S | r − 0.13S |
| 右上の点（案内あり） | 中心 (0.76S, 0.24S)、半径 0.22S。まわり 0.07S を透明にして、輪と離す | 点の中心までの距離 − 0.22S |
| 斜めの線（見えていない） | (0.2S, 0.2S) から (0.8S, 0.8S) への線、太さ 0.12S。まわり 0.08S を透明にして、輪と離す。点は描かない | 線分までの距離 − 0.06S |

- 「透明にする」は、輪の覆う割合に (1 − 透明にする範囲の覆う割合) を掛けること。範囲は、右上の点なら半径 0.22S + 0.07S、斜めの線なら太さの半分 0.06S + 0.08S。
- 色は 1 色（右上の点だけ別の色）。アルファは前もって掛けない値で持つ。右上の点は、輪と点の上に重ねる（アルファの合成）。
- 手順を JavaScript で書いたものが `mock/glyph.js`。`icons/tray-*-{16,20,24,32}.png` は、その出力（Rust で描いたものと見比べる用）。
- 大きさ: Windows の小さいアイコンの大きさ（拡大率 100% で 16、125% で 20、150% で 24、200% で 32）で描く。拡大率を取れなければ 32 で描いて Windows に縮めさせる（少しぼやける）。

### 3.2 配置

上から、監視の状態の行、案内の欄、トラッカーの表、下の行。下の行は窓の下の端に固定する。案内とトラッカーの表が窓に入りきらなければ、そのあいだだけを縦に流す（上の行と下の行は動かない）。設計の 7.4 の 1〜6 は、次のように置いた。

```
┌ ◉ OpenUT ─────────────────────────────────────────────────────── ─ □ × ┐
│  ◉ 監視中  11/28のログ                             ホストのWi-Fi情報  なし │ 1 監視の状態（左）、4 ホストのWi-Fi情報（右）
│                                                                         │
│ ┃トラッカーの追跡が始まりません                                            │ 2 案内の欄（ないときは欄ごと出さない）
│ ┃腰の電源だけを入れ直してください。                                         │
│ ┃ほかのトラッカーとドングルはそのままにしてください。                          │
│                                                                         │
│               ╭ 腰 ─────╮ ╭ 左足 ───╮ ╭ 右足 ───╮                         │ 3 トラッカーの表（1台1タイル）
│               │ [ホスト] │ │         │ │         │
│ 追跡中         │ □       │ │ □       │ │ □       │   段階の枠（下から上へ進む）
│ 位置合わせ中    │ □       │ │ □       │ │ □       │
│ 地図を同期中    │ ■ 4分   │ │ □       │ │ □       │   ■ いまの枠（経過時間）
│ Wi-Fi待ち      │ ▪       │ │ ■ 4分   │ │ ■ 3分   │   ▪ 通った枠
│ 接続済み       │ ▪       │ │ ▪       │ │ ▪       │
│ 未接続         │         │ │         │ │         │
│ 今日 ───────── │ ─────── │ │ ─────── │ │ ─────── │ 5 今日の集計（トラッカーごとの値はタイルの中）
│ 追跡できた割合  │ 94%     │ │ 91%     │ │ 88%     │
│ 追跡が途切れた  │ 2回     │ │ 3回     │ │ 4回     │
│               ╰─────────╯ ╰─────────╯ ╰─────────╯                         │
├─────────────────────────────────────────────────────────────────────────┤
│ 追跡が始まらない 1回   予期しない切断 0回               通知 ☑VR ☑デスクトップ │ 5 不具合の回数（左）、6 設定（右）
└─────────────────────────────────────────────────────────────────────────┘
```

- 左の列は、段階の名前と集計の名前を 1 回だけ書く。タイルの中の行は、どれも左の列の行と同じ高さにそろえる。
- タイルは番号の順に左から並べる（設計の 7.4 の「行の並びは番号の順」）。
- 文字はすべて左寄せ。上の行のホストの Wi-Fi 情報と、下の行の通知の切り替えだけ右に寄せる。

### 4.4 折り返しの手順（板と状態の窓で同じ）

### 6.4 表示名（画面に出すトラッカーの名前）

設計の 3.2 の名前（設定の名前か `トラッカー{N}`）を、画面に出す前に次の手順で表示名にする。状態の窓のタイル、案内の欄、VR の板、トーストで、同じ表示名を使う。どの 2 台も同じ表示名にならず、どの表示名も幅 112 px（Yu Gothic UI Bold 14 px で描いたとき）を超えない。

1. もとの名前: 設定の名前の制御文字（改行、タブなど）を空白にし、前後の空白を除く。空なら `トラッカー{N}`。
2. 幅に収める: もとの名前を Yu Gothic UI Bold 14 px で描いた幅が 112 以下なら、そのまま。超えるなら、先頭から文字の切れ目で切り、うしろに `…`（U+2026）を付けた幅が 112 以下になる最も長いものにする。
3. 同じ名前に番号を付ける: 2 の結果が、ほかのトラッカーと同じになったものは、すべて、番号の付いた形にする。番号の付いた形は、`（{N}）` の幅を 112 から引いた幅に、もとの名前を 2 と同じ手順で収め、うしろに `（{N}）` を付けたもの。N はトラッカーの番号（設計の 3.2 の `index:N` の N）。
4. 残りを確かめる: 番号の付いていない表示名が、ほかのどれかの表示名と同じなら、それにも 3 の番号を付ける。変わるものがなくなるまで繰り返す。

- 番号の付いた表示名は、末尾の `（{N}）` が台ごとに違うので、互いに同じにならない。番号の付いていない表示名は、4 が終わった時点でほかと同じものがない。繰り返しのたびに番号の付いた台が増えるので、多くても台数の回数で終わる。
- 幅は、文字の数ではなく、描いた幅で測る。字によっては全角より広い（U+2E3A を 8 文字並べると 14 px で約 216 px）。測るのは VR の板と同じ描画のクレート（設計の 7.2。`fontdue` か `ab_glyph`）で、Yu Gothic UI がなければ代わりに読んだ書体（1.1）で測る。手順は `openut_core` の関数にし、幅を測る関数を引数で受け取る（入出力をしないので、テストでは決まった幅を返す関数を渡せる）。
- 表示名は、名前の設定か、トラッカーの一覧が変わったときに計算し直す。縮めるのは見せるときだけで、設定のファイルの名前は変えない。名前の入力欄（3.5）には、縮める前の名前を入れる。
- ホストが分からないときの `ホストのトラッカー`（設計の 6.2）は、利用者の名前ではないので、この手順に入れない（4.5 で収まることを確かめた）。

例（`mock/names.js` で計算した。幅は見本の書体での値）:

| 例 | 設定の名前（番号: 名前） | 表示名 |
|---|---|---|
| 1. 長い名前の先頭が同じで、ほかに `トラッカー1` がある（`shots/window-f.png`） | 1: `腰のトラッカー（ベルトの後ろ）`、2: `腰のトラッカー（ベルトの前）`、3: `トラッカー1`、4: `⸺` を 8 文字、5: なし | 1: `腰のトラ…（1）`、2: `腰のトラ…（2）`、3: `トラッカー1`、4: `⸺⸺⸺⸺…`、5: `トラッカー5` |
| 2. 初めから同じ名前で、番号を付けた形と同じ名前もある（`shots/window-g.png`） | 1: `足`、2: `足`、3: `足（2）` | 1: `足（1）`、2: `足（2）`、3: `足（2）（3）` |
| 3. 設定の名前が、ほかの台の既定の名前と同じ | 1: `トラッカー2`、2: なし | 1: `トラッカ…（1）`、2: `トラッカ…（2）` |

- 例 1 で、1 と 2 は 2 の結果がどちらも `腰のトラッカー…` になるので番号を付ける。3 の `トラッカー1` は、ほかと同じでないので、そのまま。4 は幅で縮める。
- 例 2 で、3 の `足（2）` は、2 の番号を付けた形と同じになるので、4 で番号を付ける。
- 同じ表示名が 2 台を指さないので、R1 の案内の `{H}` で、電源を入れ直す 1 台が決まる。どの番号がどのトラッカーかは、F3 の見分け方（1 台のカメラを手で覆う）で確かめ、名前を付け直してもらう。

### 6.5 設計の文言から変えたところ

意味は変えず、言い回しだけを変えた。yomiyasu の決まりで読み直し、不自然な言い方、直訳語、助詞を落として漢語を詰めた言い方を直した。

| 場所 | 設計（7.1、7.4、PRD の W-2） | この文書 | 理由 |

| R1 の見出し | トラッカーが始まらない状態です | トラッカーの追跡が始まりません | 「トラッカーが始まる」は日本語として不自然（オーナーの指摘）。始まらないのは追跡 |

| R1 `Resolved` の見出し | 直りました | 追跡が始まらない問題が直りました | 何が直ったかを書いた（トーストと VR で単独で出るため） |

| R1 のすること | ほかのトラッカーとドングルはそのまま | ほかのトラッカーとドングルはそのままにしてください。 | 「そのまま」で切ると文が終わらない |

4. トースト: 送り主の表示、3 行目の `OpenUT`、改行、「（ほか1件）」の折り返しがどう見えるか。
5. 状態の窓: Yu Gothic UI で、字がにじまず読めるか。タイトルバーが暗くなるか。まだ通っていない段階の枠（輪郭だけ）が見えるか。窓を最小の大きさにしても、5 台のタイルが横に並び、名前、ホストのタグ、経過時間が読めるか。
6. 名前の入力: 日本語の入力（変換中の文字）が入力欄の中で見えるか。8 文字で止まるか。

## 9. 設計に書かれていなかったので決めたこと（PM に確かめたい点）
