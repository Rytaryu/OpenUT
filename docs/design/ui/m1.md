# OpenUT の画面と通知の見た目

OpenUT の主の窓、トレイのアイコン、SteamVR の中の板、デスクトップのトースト、文言の見た目を決める。最終更新: 2026-11-28（第 4 版。オーナーの 3 回目の返事のうち、見た目と言い回しの点を入れた）。

第 4 版はオーナーの 2 回目の返事（Issue #23。PRD の W-10〜W-12、D-34・D-35）と、設計の追補（PR #37）、通し版の設計（PR #60。D-40・D-41）に合わせて、全体を作り直した（Issue #28）。

- 見せるのは、利用者に要ることだけにした。準備の手引き、いまの状態（正常・待機中・異常）、異常のときにすること、トラッカーとドングルの項目。内部の状態の名前（Wi-Fi待ち、地図を同期中など）、「監視中」の印、ログの日付、集計は出さない。
- 窓は VIVE Hub の代わりになるアプリの主の窓として作った。上に全体の状態といますること、まん中にドングルとトラッカーを 1 台 1 枚の札で横に並べ、下に手引きと 3 つの操作（ペアリング、セットアップ、キャリブレーション）を置く。
- トラッカーを体の部位で呼ばない。札の名前は VIVE Hub と同じ番号で、どの台かはシリアル番号の末尾（太字）で見分ける。並びはシリアル番号の順で、つなぎ直しても札の位置は変わらない。3 台でも 5 台でも、同じ札を並べる。
- 文章に頼らず、印と色と配置で示す。状態は色と形の両方で見分けられる印（正常 ●、待機中 ◐、異常 ▲）にした。

オーナーの 3 回目の返事（#23、2026-11-28 21:19）のうち、見た目と言い回しの点は次のように直した。何をいつ見せるかに関わる点（手引きの段をやめる、キャリブレーションのボタンをやめる、VR とデスクトップの案内を分ける、設定の画面、電源を切る・ペアリングを解除するボタン、ペアリングの画面、「同期中」のような状態の語）は PM に渡した（9.2）。

- ホストは名前の前の星（★）で示し、`ホスト` の文字を出さない。
- トラッカーの絵を、前面の上に 2 つのカメラがある角の丸い胴にした。状態の色は胴の輪郭に付ける（レンズの色で分けない）。
- 札の接続の値を `接続済み`、`USB接続`、`未接続` にした（`ドングル` と書かない）。
- 操作の `地図を作る` を `セットアップ` にした（VIVE Hub の言い方）。
- 「部屋へ向けて」のように向きの分からない言い方をやめ、カメラに何を映すか（壁や家具）と、どう動かすか（ゆっくり左右に向きを変える）を書いた（6.5）。

根拠と範囲は次のとおり。

- 根拠: `docs/design/m1-watcher.md` の 3.2・5.4・5.5・7 章（PR #37 のブランチ `design/m1-user-view`。まだ main に入っていない）、`docs/design/walkthrough.md` の 2 章・4.3・5 章（PR #60 のブランチ `design/walkthrough`。まだ main に入っていない）、`docs/product/PRD.md` の W-10〜W-12・R-4・R-9、`docs/project/roles/ux.md` のオーナーの方針、Issue #23 と #28。
- **何をいつ見せるかは設計（`m1-watcher.md` の 7.1〜7.4）のまま変えていない。** この文書では配置、寸法、色、書体、印、状態ごとの見え方、文言の言い回しを決める。設計に書かれていなかったために決めたことは、9 章に並べた。
- 画面の部品は設計のとおり（主の窓は `eframe`／`egui`、トレイは `tray-icon`、トーストは `tauri-winrt-notification`、VR の中は OpenVR のオーバーレイに自前で描いた画像）。この文書の値はどれもこの部品で作れる。印と絵は、円、角の丸い四角、線、弧、多角形だけで描く（画像のファイルを使わない）。
- HTC の画像、名前、アイコンは使っていない。VIVE Hub に寄せたのは、機器を横に並べて状態と電池を見せること、ペアリングと地図の作成をボタンで始めることの 2 つ。

## 1. 共通の決まり

いちばん目立たせるのは、全体の状態と、トラッカーの絵の胴の輪郭の色。トラッカーの状態は札の上の帯、絵の胴の輪郭、状態の印の 3 か所で同じ色になる。ほかの部分は灰色の濃淡で控えめにする。

### 1.1 書体

- Yu Gothic UI だけを使う（オーナーの方針: 書体は 1 系統）。太さは Regular と Bold の 2 つだけ。
- 実行時に Windows の書体のフォルダー（`%WINDIR%\Fonts`）から読む（配布物に入れない。設計の 7.2）。ファイルは `YuGothR.ttc`（Regular）と `YuGothB.ttc`（Bold）。TTC の中の書体は番号を決め打ちせず、名前（family が `Yu Gothic UI`）で選ぶ。
- なければ、設計（7.2）の順に Meiryo UI（`meiryo.ttc`、Bold は `meiryob.ttc`）、MS ゴシック（`msgothic.ttc`。Bold はないので Regular で代える。太字の作りものはしない）。
- 大きさは次のとおり（Windows の拡大率 100% での論理の画素）。

| 使う場所 | 大きさ | 太さ |
|---|---|---|
| 全体の状態（帯の左） | 28 | Bold |
| 帯のいますること、案内の見出し | 18 | Regular（見出しは Bold） |
| 札の名前、札の状態、ドングルの状態、操作の手引きの名前 | 16 | Bold |
| 帯の案内のすること | 16 | Regular |
| 手引きの段の名前、ボタン、帯の中の欄、チェックボックスの名前 | 14 | Regular（いまの段とボタンは Bold） |
| 札の値（接続、電池、シリアル番号、ファームウェアの版）、段の進み（1/2） | 13 | Regular（電池の % と、シリアル番号の末尾と、段の進みは Bold） |

### 1.3 文言の書き方

オーナーの方針（`roles/ux.md`）のとおり、残す文字はいま何をすればよいかの 1 行、状態、数、押せる物の名前、値のラベルだけにする。説明の文と、小さい補足の文字は置かない。文言は yomiyasu で読み直した（6.5）。

- 全角と半角のあいだに空白を入れない（例: `VIVE Hubを起動してください`、`トラッカー2`）。Windows の日本語の画面の書き方に合わせた。
- 見出し（状態）は「です・ます」で言い切る。すること（1 行）は「〜してください」にする。
- 「。」のあとは、どの画面でも改行する。
- 折り返すのは、6 章の文言の「文節の切れ目」だけにする（`mock/text.js` では「|」で示した）。文言の関数（`openut_core::text`）は、文字列ではなく「行ごとの、切ってよい場所で分けた語句の並び」を返し、窓と VR の板は 4.4 の手順で折り返す。トーストは Windows が折り返す。
- 呼び名（`{T}`、`{H}`）は 1 つの語句として入れ、その中では「（」の前だけで切ってよい（長い末尾で、かっこの中が割れないように）。かっこの中が 1 行に収まらないとき（末尾が長いとき）だけ、4.4 の 3 で、かっこの中も切る。

## 2. トレイのアイコン

### 2.1 3 つの見え方

全体（設計の 7.4）の 3 つで見え方を変える。灰色のときも待機中の見え方にする（4 つ目の見え方は作らない）。

| 見え方 | マーク | 色 |
|---|---|---|
| 正常 | 輪 ＋ 点 | `icon_ok` |
| 待機中 | 右上が 90° 切れた輪 ＋ 点 | `icon_wait` |
| 異常 | 輪 ＋ 点 ＋ 右上の点 | `icon_fault` |

窓のアイコン（タイトルバーとタスクバー）も、同じマークを全体に合わせて替える（32 と 64 で描く）。

### 2.2 マークの描き方（どの大きさでも同じ手順）

大きさ S 画素の正方形に、画素ごとの「覆う割合」を計算して描く（輪郭をなめらかにするため）。画素 (x, y) の中心は (x + 0.5, y + 0.5)。中心 c = (0.5S, 0.5S)。d を「形のふちまでの距離（画素。内側が負）」とすると、覆う割合は clamp(0.5 − d, 0, 1)。

| 部品 | 形（S に対する割合） | d |
|---|---|---|
| 輪 | 中心線の半径 0.34S、太さ 0.16S | \|r − 0.34S\| − 0.08S（r は c からの距離） |
| 点 | 半径 0.13S | r − 0.13S |
| 輪の切れ目（待機中） | 輪の 315°（右から時計回り。右上）を中心に 90° を抜く | 輪の覆う割合に clamp(0.5 + e, 0, 1) を掛ける。e は、その画素の角度から切れ目の端までの角度（ラジアン）× 0.34S |
| 右上の点（異常） | 中心 (0.76S, 0.24S)、半径 0.22S。まわり 0.07S を透明にして、輪と離す | 点の中心までの距離 − 0.22S |

- 「透明にする」は、輪と点の覆う割合に (1 − 半径 0.29S の円の覆う割合) を掛けること。右上の点はその上に重ねる（アルファの合成）。
- 色は 1 色。アルファは前もって掛けない値で持つ。
- 手順を JavaScript で書いたものが `mock/glyph.js`。`icons/tray-{ok,wait,fault}-{16,20,24,32}.png` と `icons/toast-{fault,ok}-96.png` は、その出力（`node docs/design/ui/mock/export.js` で書き出す。Rust で描いたものと見比べる用）。
- 大きさ: Windows の小さいアイコンの大きさ（拡大率 100% で 16、125% で 20、150% で 24、200% で 32）で描く。拡大率を取れなければ 32 で描いて Windows に縮めさせる（少しぼやける）。

### 2.3 指を置いたときの 1 行とメニュー

設計（7.4 のトレイ）の決まりで、次の形にする。

| 場合 | 1 行 |
|---|---|
| ふつう | `{全体}　{a}/{b}`（a は正常の台数、b は未接続でない台数）。例: `正常 3/3`、`待機中 2/3` |
| 異常 | `異常：{最も優先度の高い案内の見出し}`。例: `異常：トラッカーの追跡が始まりません` |
| `line` が `Health` のとき、VIVE Hub が止まっているとき | `待機中：{line の 1 行}`。例: `待機中：VIVE Hubを起動してください` |
| 追いつき、起動の途中（`line` なし） | `待機中` |

- 「：」は全角。見出しと 1 行は「|」と「\n」を除いて 1 行にする。Windows は 127 文字で切るので、越えたら 126 文字と `…` にする。
- メニュー（右クリック）: `状態を開く`、区切り、`終了`。左クリックでも主の窓を開く（設計の 7.4）。

### 3.4 機器の並び

ドングルの札を左に置き、1 px の線（`line`。左右 12）で区切って、トラッカーの札を横に並べる。札のあいだは 12。並びの高さは 245 以上（トラッカーが 0 台でも下の段が動かないように）。シリアル番号が 2 行以上になって伸びた札があれば、並びのすべての札とドングルの札を、その札の高さにそろえる。

| 項目 | 値 |
|---|---|
| ドングルの札 | 幅 120。地 `panel`、丸み 8。上から: 内側 14、名前 `ドングル`（16 Bold、中央）、8、絵 60 × 48、8、状態（16 Bold、中央）。状態は `接続済み`（`ink`）、`未接続`（`ink_2`）、`—`（分からない。`ink_2`）。絵は 1.4 のとおり |
| トラッカーの札の幅 | clamp(floor((A − 48) ÷ 5), 152, 176)。A は「窓の幅 − 40 − 120 − 25」。最初の大きさで 176、最小の大きさで 153 |
| 横に送る | 札の数 × 幅 ＋ 12 ×（数 − 1）が A を超えたら、横の `ScrollArea` に入れる。右の端 40 を地の色へぼかし、札の下 6 に高さ 4 の送りの棒（地 `panel_2`、つまみ `idle`）を出す |
| トラッカーが 0 台 | 1 枚目の札の場所に、輪郭だけの札（1.5 px、`line`）と、まん中にトラッカーの絵（輪郭、`line`）を置く。文字は置かない |

トラッカーの札は上から次の段に分ける（内側 上 14・左右 12・下 12、地 `panel`、丸み 8）。

| 段 | 値 |
|---|---|
| 上の帯 | 札の上の端に高さ 4、状態の色（状態がなければ出さない） |
| 名前 | 16 Bold、行の高さ 22、中央。VIVE Hub の番号があれば `トラッカー{N}`、なければ `トラッカー`（6.4）。ホストなら、名前の前にホストの星 16（`accent`）と間 4 を置き、星と名前の組を中央にそろえる |
| 絵 | 上 8、60 × 48、中央。胴の輪郭を状態の色（状態がなければ `idle`）。未接続なら輪郭だけ |
| 状態 | 上 8、高さ 22。印 14 ＋ 6 ＋ 名前 16 Bold、中央。名前は状態の色。状態がなく未接続なら、未接続の印（`idle`）と `未接続`（`ink_2`） |
| 区切り | 上下 8、1 px（`line`） |
| 接続と電池 | 13、行の高さ 20。接続は 印 16 ＋ 6 ＋ `接続済み`（ドングルを通して）・`USB接続`・`未接続`（印は `ink_2`）。電池は 印 26 × 14 ＋ 6 ＋ `{p}%`（Bold）。札の内側が 148 以上なら 1 行に左右に分けて置き、狭ければ 2 行にする |
| シリアル番号 | 上 6 にラベル `シリアル番号`（12、`ink_2`）、その下に値（13、行の高さ 18）。末尾（呼び名の末尾と同じ長さ）を Bold・`ink`、その前を Regular・`ink_2`。札の幅に収まらないときの形は、この節の終わり |

台ごとの違いは次のとおり（設計の 7.4 の「トラッカーの項目」）。

| 場合 | 見え方 |
|---|---|
| 未接続で、異常でない（状態がない） | 上の帯なし、絵は輪郭だけ、名前は `ink_2`。状態の段に `未接続`。接続と電池の段は出さない（状態の段で未接続と分かるため） |
| 未接続で、異常（R4 の切れた台、R1 の接続の終わったホスト） | 上の帯と胴の輪郭と状態が `fault`。絵は輪郭だけ。接続の段に `未接続`（電波に斜めの線）。電池は出さない |
| 電池が分からない（つながっていて `battery` がない） | 電池の外枠だけと `—`（0% と見せない） |
| 充電中 | 電池の印に稲妻を重ねる。文字は足さない |
| シリアル番号が分からない（仮の台） | 値に `—`。名前は `トラッカー`（ホストなら前に星が付く） |
| ファームウェアの版が分からない | 値に `—` |
| ホスト | 名前の前の星。ホストが替わったら、星だけが移る（札の位置は変わらない） |

- 札の並びは設計の 7.4 の「並べ方」（シリアル番号の順。仮の台は最後）のまま。並びと札の幅は接続、ホスト、台数で変わらない。
- 札の名前の番号はつないだ台だけに付く（設計の 3.2）。つなぎ直して番号が変わっても、札の位置は変わらず、名前の番号だけが替わる。どの台かはシリアル番号の末尾（太字）で見分ける。
- シリアル番号の値は末尾（太字）をいつもすべて見せる。次の 3 つのうち、最初に当てはまる形にする。幅は札の内側（最小の大きさで 129、最初の大きさで 152）。
  1. 全体が 1 行に収まる: 全体を 1 行に出す。ふつうの 13 文字は、全体が末尾でも収まる（3.8）。
  2. `…` と末尾が 1 行に収まる: 末尾より前を前から削り、先頭に `…` を付けて 1 行に出す。
  3. 末尾だけでも 1 行に収まらない（設計の 3.2 では、末尾はシリアル番号の全体まで延び、設計の 4.4 では最長 32 文字。1 行に収まる長さは 3.8）: 末尾より前は出さない。`…`（末尾より前があるときだけ）と末尾を末尾の側から幅いっぱいずつ行に分け、残った文字を 1 行目に置く。行の高さは 18 のまま。行の数に上限はない（32 文字で、見本の文字なら 2〜3 行、`W` だけなら 3〜4 行。3.8）。
- 3 で末尾の側から分けるのは、シリアル番号の終わりの文字をふだんの 1 行の形のまま続けて見せるため。長い末尾どうしは先頭の 1 文字が違う（設計の 3.2 が、重ならない最も短い長さを選ぶため）ので、その文字が 1 行目に離れて置かれ、目に入りやすい。例（`window-j.png`。最小の大きさ）: `A7` / `KWM3X9QH2VT8ND` / `4ZR6BY0PC5FJ0001`。案内の呼び名の `（…A7KWM3X9QH2VT8ND4ZR6BY0PC5FJ0001）` と、文字の並びは同じ。

### 4.4 折り返しの手順（板と主の窓で同じ）

文言の関数は行ごとに、切ってよい場所で分けた語句の並びを返す（1.3、6 章）。行（「。」で分けたもの）ごとに、次のとおり詰める。

1. いまの行に次の語句を足しても幅に収まるなら、足す。
2. 収まらず、その語句が 1 行の幅に収まるなら、いまの行を確定して（空なら確定しない）、次の行をその語句から始める。
3. 1 つの語句だけで 1 行の幅を超えるとき（末尾の長い呼び名の `（…{末尾}）の` など）は、いまの行を確定せずに、その語句を 1 文字ずつ続けて詰め、行がいっぱいになったら折り返す。次の 2 つを守る。
   - 行の先頭に `、。，．）」』ー…` と小さい仮名（`ぁぃぅぇぉっゃゅょゎァィゥェォッャュョヮ`）が来ないように、前の行の終わりの文字を次の行へ送る。
   - シリアル番号に使える文字（ASCII の英数字と `-`。設計の 4.4）の続きは、続き全体が 1 行に収まるなら途中で切らず、続きの初めから次の行へ送る。1 行に収まらない続き（末尾が長いとき）は、行がいっぱいになったところで切る。どの行も幅を超えない。

例（板。末尾が 32 文字の呼び名）: `トラッカー1（…A7KWM3X9QH2VT8ND4Z` / `R6BY0PC5FJ0001）の電源だけを` / `入れ直してください。` / `ほかのトラッカーとドングルは、` / `そのままにしてください`（`vr-serial32.png`）。

幅は、板が 1044 画素（見出しとすることで同じ）、主の窓の帯と帯の中の欄が 3.3 の幅、手引きの段の名前が 3.5 の幅。窓の幅を変えたら、そのときの幅で計算し直す。手順を JavaScript で書いたものが `mock/wrap.js` の `wrap`（見本の文字は、これで折り返している）。札のシリアル番号は文の中の語句ではないので、この手順を使わず、3.4 の形で分ける（`mock/wrap.js` の `wrapFromEnd`）。

|---|---|---|

## 9. 設計に書かれていなかったので決めたこと（PM・設計に確かめたい点）

### 9.1 この文書で決めたこと

1. **帯の中の欄から、`line` の案内を除く**（3.3）。設計の 7.4 は状態の窓の 1（いますること）と 2（異常の案内の欄）を別に置くが、異常のときは同じ案内が 2 回出る。帯の中で 1 回だけにした。欄にほかの案内がなければ、欄を出さない。
2. **R2〜R5 のすることから、見出しと同じ `{T}` を除く**（6.1、6.5）。どの画面でも、することは見出しのすぐ下か右に出るため。第 3 版から PM に聞いている点（第 3 版の 9 章の 4）。
3. **全体が正常のときも、手引きをたたまない**（3.5）。たたむと、下の段の位置が状態で変わり、操作のボタンを探す場所が動くため。
4. **3 つの操作のボタンを押せる条件と、押したときにすること**（3.5）。設計（#57）で決めてほしい。たとえば、VIVE Hub が動いているあいだ（M1）に押せるか、キャリブレーションを主の窓から押したときに何をするか（VR の中の板で始める操作のため。`walkthrough.md` の 4.3）。見た目は押せる・その操作をしている・押せない の 3 つを用意した。表示の写し（`DisplayModel`）に、ボタンごとの状態と、操作の手引きの段（名前、済んだ・いま、進み具合）を足すことになる。
5. **札の名前に末尾を入れない**（6.4）。末尾はシリアル番号の値の太字で示す。
6. **未接続の札では接続と電池の段を出さない**（3.4）。状態の段に `未接続` を出すため。
7. **電池が少なくても色を変えない**（3.4）。設計の 7.4（W-11 は見せるだけ。案内にするかは 14 章で PM に聞く）に合わせた。少ないときに色を変えるかは、PM の判断のあとで決める。
8. **トーストの 3 行目に `OpenUT`**（5 章）。送り主が PowerShell の ID のあいだだけ。第 3 版から PM に聞いている点。
9. **主の窓をいつも暗い表示にする**（1.2）。第 3 版から PM に聞いている点。
10. **トラッカーが 0 台のとき、輪郭だけの札を 1 枚置く**（3.4）。文字は置かない。
11. **ダッシュボードの板の札ではシリアル番号の全体、版、接続、電池を出さない**（4.6）。VR の中で読める大きさにすると 5 枚が並ばないため。どれも主の窓で見られる。
12. **通し版の手引き**: 設計の G1 は「VIVE Hub を起動する」だが、通し版（VIVE Hub を使わない）では当たらない。通し版の手引きの段は #57 で決めてほしい（見た目は、段の数が変わっても同じ並べ方で作れる）。

13. **ホストの星を札の名前の前に置く**（3.4）。VIVE Hub の星の位置は、画像を見られなかったので確かめていない。
14. **星は塗った形（★）にする**（1.4）。オーナーの返事の記号は ☆ だが、16 px で見分けやすいように塗った。
15. **状態の色をトラッカーの絵の胴の輪郭に付ける**（1.4）。カメラは状態で色を変えない。

設計と通し版の設計のあいだで気づいた食い違い: なし（上の 4 と 12 は、通し版の設計がまだ決めていないこと）。

### 9.2 オーナーの 3 回目の返事のうち、PM に渡した点
