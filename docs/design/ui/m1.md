# OpenUT の画面と通知の見た目

OpenUT のメインウィンドウの見た目と文言を決める。トレイのアイコン、VR 内のオーバーレイ、トースト通知は、第 4 版の形を仮に残した。最終更新: 2026-11-28（第 5 版）。

第 5 版はオーナーの 3 回目の返事（#23、2026-11-28 21:19）と PM の答え（PR #21 の 2026-11-28 21:23・21:32・22:11 のコメント。PRD の W-5、W-10、W-13、W-14、R-4、D-46、D-48）に合わせて、メインウィンドウを作り直した。

- 準備の手順の手引き（G1〜G5）を出さない。手引きの枠をやめた。
- キャリブレーションのボタンを置かない。下の行に置く操作のボタンは `ペアリング` と `セットアップ` の 2 つにした。
- 設定を開く歯車のボタンと、カードから開くメニュー（電源を切る、ペアリングを解除。中身は仮）の場所を取った。画面の中身は #76 で作る。
- カードの語を VIVE Hub に寄せ、接続と状態を 1 語で示す（`接続済み`、`同期中`、`未接続` など。仮）。ホストは名前の前の ★ で示し、どの文言にも「ホスト」と書かない。
- 「追跡」を、VR でふつうに使う「トラッキング」にした（D-48）。
- トラッカーのアイコンを大きくし、状態の色を胴の輪郭に付けた。
- トレイ、トースト通知、VR 内のオーバーレイは、通知の出し先（W-5。#57）が決まってから作り直す（#76）。それまでは第 4 版の形を仮に残し、文言だけを第 5 版に合わせた。ダッシュボードのオーバーレイ（第 4 版の 4.6）は外した。

根拠と範囲は次のとおり。

- 根拠: `docs/design/m1-watcher.md` の 3.2、5.4、5.5、7 章、`docs/product/PRD.md` の W-5、W-10〜W-14、R-4、`docs/project/roles/ux.md` のオーナーの方針、Issue #23、#28、#76、PR #21 の PM のコメント。
- **何をいつ見せるかは設計（`m1-watcher.md` の 7.1〜7.4）に従う。** PM の答えで変わった点（手引きをやめる、キャリブレーションのボタンをやめる、「ホスト」と書かない、VIVE Hub の言葉に合わせる）は、PRD に入っているが、設計にはまだ入っていない。この文書で合わせた点を 10 章に並べた（設計担当に直してもらう）。
- 画面の部品は設計のとおり（メインウィンドウは `eframe`／`egui`、トレイは `tray-icon`、トースト通知は `tauri-winrt-notification`、VR 内は OpenVR のオーバーレイに自前で描いた画像）。この文書の値はどれもこの部品で作れる。アイコンは円、角の丸い四角、線、弧、多角形だけで描く（画像のファイルを使わない）。
- HTC の画像、名前、アイコンは使っていない。VIVE Hub の画面と公式の案内のページ（www.vive.com）は、この環境から開けなかった。VIVE Hub に寄せた点はオーナーの返事の言葉による。VIVE Hub の言い方として確かめたい点は 8.1 に並べた。

## 1. 共通の決まり

いちばん目立たせるのは、全体の状態と、トラッカーのアイコンの輪郭の色。トラッカーの状態はカードの上の線、アイコンの輪郭、状態の印の 3 か所で同じ色になる。ほかの部分は灰色の濃淡で控えめにする。

### 1.1 書体

- Yu Gothic UI だけを使う（オーナーの方針: 書体は 1 系統）。太さは Regular と Bold の 2 つだけ。
- 実行時に Windows の書体のフォルダー（`%WINDIR%\Fonts`）から読む（配布物に入れない。設計の 7.2）。ファイルは `YuGothR.ttc`（Regular）と `YuGothB.ttc`（Bold）。TTC の中の書体は番号を決め打ちせず、名前（family が `Yu Gothic UI`）で選ぶ。
- なければ、設計（7.2）の順に Meiryo UI（`meiryo.ttc`、Bold は `meiryob.ttc`）、MS ゴシック（`msgothic.ttc`。Bold はないので Regular で代える。太字の作りものはしない）。
- 大きさは次のとおり（Windows の拡大率 100% での論理ピクセル）。

| 使う場所 | 大きさ | 太さ |
|---|---|---|
| 全体の状態（ステータスバーの左） | 28 | Bold |
| ステータスバーの 1 行、案内の見出し | 18 | Regular（見出しは Bold） |
| カードの名前、カードの語、ドングルの語 | 16 | Bold |
| ステータスバーの案内のすること | 16 | Regular |
| ボタン、案内の一覧、チェックボックスの名前、メニューの項目 | 14 | Regular（ボタンと一覧の見出しは Bold） |
| カードの値（電池、シリアル番号、ファームウェアのバージョン） | 13 | Regular（電池の % と、シリアル番号の末尾は Bold） |
| カードのラベル（シリアル番号、ファームウェア）、下の行の「通知」 | 12 | Regular |

ファイル名は Windows 10・11 の日本語版で一般的なもの。日本語以外の Windows にあるかは確かめていない（設計の 14 章と同じ）。

### 1.3 文言の書き方

オーナーの方針（`roles/ux.md`）のとおり、残す文字はいま何をすればよいかの 1 行、状態、数、押せる物の名前、値のラベルだけにする。説明の文と、小さい補足の文字は置かない。文言は yomiyasu で推敲した。

- 全角と半角のあいだに空白を入れない（例: `VIVE Hubを起動してください`、`トラッカー2`）。Windows の日本語の画面の書き方に合わせた。
- 見出し（状態）は「です・ます」で言い切る。すること（1 行）は「〜してください」にする。
- 「。」のあとは、どの画面でも改行する。
- 折り返すのは、3 章の文言の文節の区切りだけにする（`mock/text.js` では「|」で示した）。文言の関数（`openut_core::text`）は、文字列ではなく「行ごとの、切ってよい場所で分けた語句の並び」を返し、メインウィンドウと VR 内のオーバーレイは 5.4 の手順で折り返す。トースト通知は Windows が折り返す。
- 呼び名（`{T}`、`{H}`）は 1 つの語句として入れ、その中では「（」の前だけで切ってよい（長い末尾で、かっこの中が割れないように）。かっこの中が 1 行に収まらないとき（末尾が長いとき）だけ、5.4 の 3 で、かっこの中も切る。
- 「ホスト」の語はどの文言にも使わない（PM の答えの 7）。ホストは ★ で示し、案内では台の呼び名で示す（3.4）。

## 2. メインウィンドウ

### 2.1 ウィンドウ

| 項目 | 値 |
|---|---|
| タイトル | `OpenUT` |
| 大きさ（クライアント領域。論理ピクセル） | 最初は 1120 × 640。最小 1000 × 600。大きさを変えられる。どの大きさでも横長 |
| タイトルバー | 暗くする（`ViewportBuilder::with_theme` などで、winit の暗いテーマを指定する。Windows 11 では暗いタイトルバーになる） |
| アイコン | マーク（4.1。全体に合わせて替える） |
| 閉じたとき | 隠すだけ（設計の 7.4） |
| 縦が足りないとき | 下の行（2.6）をウィンドウの下に固めたまま、上の中身を縦にスクロールする（egui の縦の `ScrollArea`）。カードの中身が入りきらないとき（最小の大きさで案内が多いとき、シリアル番号が 3 行以上になってカードが伸びたとき）だけ、スクロールする（`window-j.png`） |

最初の 640 は 1920 × 1080 の画面を 150% で使うとき（論理ピクセルで 1280 × 720。タスクバーとタイトルバーを引くと 640 ほど）に収まる高さ。

### 2.2 配置

```
┌ タイトルバー（Windows。暗い）OpenUT ─────────────────────────────────┐
│ ┌ 1 ステータスバー ─────────────────────────────────────────────┐ │
│ │ ◐ 待機中 │ いますること（18）                [フォルダーを選ぶ]│ │
│ │          │ ─ 案内の一覧（ほかの案内。あるときだけ）           │ │
│ └──────────────────────────────────────────────────────────┘ │
│ ┌ 2 機器 ─────────────────────────────────────────────────────┐ │
│ │[ドングル]│[★トラッカー2][トラッカー1][トラッカー ] …（横にスクロール）│ │
│ │          │  アイコン    アイコン    アイコン                  │ │
│ │          │  ● 接続済み  ◐ 同期中   ○ 未接続                  │ │
│ │          │  電池・シリアル番号・ファームウェア・[…]             │ │
│ └──────────────────────────────────────────────────────────┘ │
├ 3 下の行: [ペアリング][セットアップ]   通知 ☑VR内 ☑デスクトップ │ [⚙] ┤
└──────────────────────────────────────────────────────────────┘
```

設計の 7.4 の「状態の窓に置くもの」との対応: 1 は、設計の 1（全体、いますること、フォルダーを選ぶ）と 2（異常の案内の欄）。2 は、設計の 4（ドングル）と 5（トラッカー）。3 は、設計の 6（通知の設定）と、#28 で足した操作のボタン（ペアリング、セットアップ）と、設定のボタン（W-13）。設計の 3（手引き）は置かない（W-10、D-46）。

- 左右と上の余白は 20、ステータスバーと機器のあいだは 16、機器の下は 16。文字は左にそろえる。カードの上半分（名前、アイコン、カードの語）だけは、カードの中央にそろえる。
- 上から、いまの状態（ステータスバー）→ どの台がどうか（機器）→ 操作と設定（下の行）の順に読める並びにした。VIVE Hub と同じく、機器を横に並べ、1 台ずつアイコンと状態と電池を見せる。
- 機器の並びは残りの高さいっぱいに伸ばす（2.4）。手引きの枠をやめて空いた高さは、カードを大きくするのに使った。

- カードの名前の番号はつないだ台だけに付く（設計の 3.2）。つなぎ直して番号が変わっても、カードの位置は変わらず、名前の番号だけが替わる。どの台かはシリアル番号の末尾（太字）で見分ける。
- シリアル番号の値は末尾（太字）をいつもすべて見せる。次の 3 つのうち、最初に当てはまる形にする。幅はカードの内側（最小の大きさで 129、最初の大きさで 152）。
  1. 全体が 1 行に収まる: 全体を 1 行に出す。ふつうの 13 文字は、全体が末尾でも収まる（2.8）。
  2. `…` と末尾が 1 行に収まる: 末尾より前を前から削り、先頭に `…` を付けて 1 行に出す。
  3. 末尾だけでも 1 行に収まらない（設計の 3.2 では、末尾はシリアル番号の全体まで延び、設計の 4.4 では最長 32 文字）: 末尾より前は出さない。`…`（末尾より前があるときだけ）と末尾を、末尾の側から幅いっぱいずつ行に分け、残った文字を 1 行目に置く。行の高さは 18 のまま。行の数に上限はない（32 文字で、モックアップの文字なら 2〜3 行、`W` だけなら 3〜4 行。2.8）。
- 3 で末尾の側から分けるのは、シリアル番号の終わりの文字を、ふだんの 1 行の形のまま続けて見せるため。長い末尾どうしは先頭の 1 文字が違う（設計の 3.2 が、重ならない最も短い長さを選ぶため）ので、その文字が 1 行目に離れて置かれ、目に入りやすい。例（`window-j.png`。最小の大きさ）: `A7` / `KWM3X9QH2VT8ND` / `4ZR6BY0PC5FJ0001`。案内の呼び名の `（…A7KWM3X9QH2VT8ND4ZR6BY0PC5FJ0001）` と、文字の並びは同じ。
- シリアル番号が 2 行以上になったカードがあると、中身の高さの最大が 18 ずつ増え、並びのすべてのカードがその高さにそろう（余った高さから引く。足りなければ縦にスクロールする）。

### 2.9 egui での作り方の目安

| 項目 | 値 |
|---|---|
| 配置 | 下の行は `TopBottomPanel::bottom`、残りは `CentralPanel` の中の縦の `ScrollArea`。トラッカーのカードの並びは、横の `ScrollArea` に入れる（ドングルのカードと区切りの線は外に置く） |

### 4.2 マークの描き方（どの大きさでも同じ手順）

大きさ S ピクセルの正方形に、ピクセルごとの「覆う割合」を計算して描く（輪郭をなめらかにするため）。ピクセル (x, y) の中心は (x + 0.5, y + 0.5)。中心 c = (0.5S, 0.5S)。d を「形のふちまでの距離（ピクセル。内側が負）」とすると、覆う割合は clamp(0.5 − d, 0, 1)。

| 部品 | 形（S に対する割合） | d |
|---|---|---|
| 輪 | 中心線の半径 0.34S、太さ 0.16S | \|r − 0.34S\| − 0.08S（r は c からの距離） |
| 点 | 半径 0.13S | r − 0.13S |
| 輪の欠け（待機中） | 輪の 315°（右から時計回り。右上）を中心に 90° を抜く | 輪の覆う割合に clamp(0.5 + e, 0, 1) を掛ける。e は、そのピクセルの角度から欠けた所の端までの角度（ラジアン）× 0.34S |
| 右上の点（異常） | 中心 (0.76S, 0.24S)、半径 0.22S。まわり 0.07S を透明にして、輪と離す | 点の中心までの距離 − 0.22S |

- 「透明にする」は、輪と点の覆う割合に (1 − 半径 0.29S の円の覆う割合) を掛けること。右上の点はその上に重ねる（アルファの合成）。
- 色は 1 色。アルファは前もって掛けない値で持つ。
- 手順を JavaScript で書いたものが `mock/glyph.js`。`icons/tray-{ok,wait,fault}-{16,20,24,32}.png` と `icons/toast-{fault,ok}-96.png` は、その出力（`node docs/design/ui/mock/export.js` で書き出す。Rust で描いたものと見比べる用）。
- 大きさ: Windows の小さいアイコンの大きさ（拡大率 100% で 16、125% で 20、150% で 24、200% で 32）で描く。拡大率を取れなければ 32 で描いて、Windows に縮めさせる（少しぼやける）。

| 場合 | 1 行 |
|---|---|

### 5.4 折り返しの手順（オーバーレイとメインウィンドウで同じ）

文言の関数は行ごとに、切ってよい場所で分けた語句の並びを返す（1.3、3 章）。行（「。」で分けたもの）ごとに、次のとおり詰める。

1. いまの行に次の語句を足しても幅に収まるなら、足す。
2. 収まらず、その語句が 1 行の幅に収まるなら、いまの行を確定して（空なら確定しない）、次の行をその語句から始める。
3. 1 つの語句だけで 1 行の幅を超えるとき（末尾の長い呼び名の `（…{末尾}）の` など）は、いまの行を確定せずに、その語句を 1 文字ずつ続けて詰め、行がいっぱいになったら折り返す。次の 2 つを守る。
   - 行の先頭に `、。，．）」』ー…` と小さい仮名（`ぁぃぅぇぉっゃゅょゎァィゥェォッャュョヮ`）が来ないように、前の行の終わりの文字を次の行へ送る。
   - シリアル番号に使える文字（ASCII の英数字と `-`。設計の 4.4）の続きは、続き全体が 1 行に収まるなら途中で切らず、続きの初めから次の行へ送る。1 行に収まらない続き（末尾が長いとき）は、行がいっぱいになったところで切る。どの行も幅を超えない。

例（オーバーレイ。末尾が 32 文字の呼び名）: `トラッカー1（…A7KWM3X9QH2VT8ND4` / `ZR6BY0PC5FJ0001）の電源だけを` / `入れ直してください。` / `ほかのトラッカーとドングルは、` / `そのままにしてください`（`vr-serial32.png`）。

幅は、オーバーレイが 1044 ピクセル（見出しとすることで同じ）、メインウィンドウのステータスバーと案内の一覧が 2.3 の幅。ウィンドウの幅を変えたら、そのときの幅で計算し直す。手順を JavaScript で書いたものが `mock/wrap.js` の `wrap`（モックアップの文字は、これで折り返している）。カードのシリアル番号は文の中の語句ではないので、この手順を使わず、2.4 の形で分ける（`mock/wrap.js` の `wrapFromEnd`）。
