# OpenUT の画面と通知の見た目

OpenUT のメインウィンドウの見た目と文言を決める。トレイのアイコン、VR 内のオーバーレイ、トースト通知は、第 4 版の形を仮に残した。最終更新: 2026-11-28（第 6 版）。

第 6 版では、オーナーの 4 回目の返事（#23、2026-11-28 22:58）と、PM のコメント（PR #21 の 2026-11-28 22:54 と 23:01）に合わせて、メインウィンドウの見た目を作り直した。出す情報と、それをいつ出すかは、第 5 版から変えていない。

- トラッカーをカードで並べるのをやめ、VIVE Hub と同じく表の行で並べた。行の高さは決まっていて、台数が増えたら、同じ形の行が増えるだけになる（2.5）。
- 状態の色を VIVE Hub に合わせた。緑は正常（`接続済み`、`USB接続`）、青は待機中（`同期中`）、灰色は未接続。異常の赤は OpenUT で足した（1.2）。
- トラッカーの絵を描き直した。横長の角の丸い胴と、その中のひと回り小さい枠と、左右の端の点で描く。つながっている台は明るく、つながっていない台は暗く描く。状態の色は絵に付けず、状態の列の印と語で示す（1.4）。
- 上のステータスパネルの高さを固定した。ドングルはパネルの右に入れた（2.3）。
- ペアリングとセットアップは、VIVE Hub と同じく、名前と右端のボタンの組にした（`トラッカーのペアリング` と `新規ペアリング`、`トラッカーのセットアップ` と `設定の開始`。2.4）。
- 通知の設定（VR 内、デスクトップ）を、メインウィンドウから外した。設定の画面に入れる（#76）。
- 長いシリアル番号とファームウェアのバージョンは、行の中で折り返して全文を見せる。`…` で省略しない（2.5）。
- R3 のすることを、VIVE Hub の案内の意味（カメラを外に向け、胸の前で持つ）に合わせた（3.1）。

根拠と範囲は次のとおり。

- 根拠: `docs/design/m1-watcher.md` の 3.2、5.4、5.5、7 章、`docs/product/PRD.md` の W-5、W-10〜W-14、R-4、`docs/project/roles/ux.md` のオーナーの方針、Issue #23、#28、#76、PR #21 の PM のコメント（2026-11-28 の 22:11、22:54、23:01）。
- **何をいつ見せるかは設計（`m1-watcher.md` の 7.1〜7.4）に従う。** PM が決めたが、設計にはまだ入っていない点を、10 章に並べた（設計担当に直してもらう）。
- 画面の部品は設計のとおり（メインウィンドウは `eframe`／`egui`、トレイは `tray-icon`、トースト通知は `tauri-winrt-notification`、VR 内は OpenVR のオーバーレイに自前で描いた画像）。この文書の値はどれもこの部品で作れる。アイコンは円、角の丸い四角、線、弧、多角形だけで描く（画像のファイルを使わない）。
- HTC の画像、名前、アイコンは使っていない。VIVE Hub の画面はこの環境から開けなかった。PM がオーナーの画像を見て文章にしたもの（PR #21 の 23:01 のコメント）を手がかりにした。トラッカーの絵はその文章にある輪郭の特徴をもとに描き、VIVE のロゴは描いていない。

## 1. 共通の決まり

目立たせるのは、全体の状態（ステータスパネルの左）と、表の状態の列の印と語。ほかの部分は紺の濃淡で控えめにし、線や影の飾りを足さない。SteamVR や VR のアプリと並べて使うので、全体を暗い配色にした。

### 1.1 書体

- Yu Gothic UI だけを使う（オーナーの方針: 書体は 1 系統）。太さは Regular と Bold の 2 つだけ。
- 実行時に Windows の書体のフォルダー（`%WINDIR%\Fonts`）から読む（配布物に入れない。設計の 7.2）。ファイルは `YuGothR.ttc`（Regular）と `YuGothB.ttc`（Bold）。TTC の中の書体は番号を決め打ちせず、名前（family が `Yu Gothic UI`）で選ぶ。
- なければ、設計（7.2）の順に Meiryo UI（`meiryo.ttc`、Bold は `meiryob.ttc`）、MS ゴシック（`msgothic.ttc`。Bold はないので Regular で代える。太字の作りものはしない）。
- 大きさは 12、13、14、16、22 の 5 つ（Windows の拡大率 100% での論理ピクセル）。

| 使う場所 | 大きさ | 太さ |
|---|---|---|
| 全体の状態（ステータスパネルの左） | 22 | Bold |
| ステータスパネルの 1 行、案内の見出し、トラッカーの名前 | 16 | Regular（見出しと名前は Bold） |
| 案内のすること、案内の一覧、操作の名前、ボタン、表の値（状態、バッテリー、ファームウェア）、台数、メニューの項目、ドングルの語 | 14 | Regular（ボタン、状態の語、ドングルの語、案内の一覧の見出し、台数の数は Bold） |
| シリアル番号、表の列の見出し、「すべてオフにする」 | 13 | Regular（シリアル番号の末尾と「すべてオフにする」は Bold） |
| ドングルの名前 | 12 | Regular |

ファイル名は Windows 10・11 の日本語版で一般的なもの。日本語以外の Windows にあるかは確かめていない（設計の 14 章と同じ）。

### 1.3 文言の書き方

オーナーの方針（`roles/ux.md`）のとおり、残す文字は、いま何をすればよいかの 1 行、状態、数、押せる物の名前、列の見出しだけにする。説明の文と、小さい補足の文字は置かない。文言は yomiyasu で推敲した。

- 全角と半角のあいだに空白を入れない（例: `VIVE Hubを起動してください`、`トラッカー2`）。Windows の日本語の画面の書き方に合わせた。
- 見出し（状態）は「です・ます」で言い切る。すること（1 行）は「〜してください」にする。
- 「。」のあとは、どの画面でも改行する。
- 折り返すのは、3 章の文言の文節の区切りだけにする（`mock/text.js` では「|」で示した）。文言の関数（`openut_core::text`）は、文字列ではなく「行ごとの、切ってよい場所で分けた語句の並び」を返し、メインウィンドウと VR 内のオーバーレイは 5.4 の手順で折り返す。トースト通知は Windows が折り返す。
- 呼び名（`{T}`、`{H}`）は 1 つの語句として入れ、その中では「（」の前だけで切ってよい（長い末尾で、かっこの中が割れないように）。かっこの中が 1 行に収まらないとき（末尾が長いとき）だけ、5.4 の 3 で、かっこの中も切る。
- 「ホスト」の語はどの文言にも使わない（PM の 22:11 の 7）。ホストは ★ で示し、案内では台の呼び名で示す（3.3）。
- 操作と列の見出しの言葉は、VIVE Hub の言葉を使う（PM の 23:01 の 7）: `新規ペアリング`、`設定の開始`、`現在トラッキング中`、`すべてオフにする`、`PCトラッカー`、`状態`、`ファームウェア`、`アクション`、`同期中`。

## 2. メインウィンドウ

### 2.1 ウィンドウ

| 項目 | 値 |
|---|---|
| タイトル | `OpenUT` |
| 大きさ（クライアント領域。論理ピクセル） | 最初は 1120 × 640。最小 1000 × 600。大きさを変えられる。どの大きさでも横長 |
| タイトルバー | 暗くする（`ViewportBuilder::with_theme` などで、winit の暗いテーマを指定する。Windows 11 では暗いタイトルバーになる） |
| アイコン | マーク（4.1。全体に合わせて替える） |
| 閉じたとき | 隠すだけ（設計の 7.4） |
| 縦が足りないとき | 中身の全体を縦にスクロールする（egui の縦の `ScrollArea` を 1 つ）。右の端に幅 4 のスクロールバー（`idle`） |

最初の 640 は、1920 × 1080 の画面を 150% で使うとき（論理ピクセルで 1280 × 720。タスクバーとタイトルバーを引くと 640 ほど）に収まる高さ。案内の一覧がなければ、トラッカーが 6 台まではスクロールせずに見える。

### 4.2 マークの描き方（どの大きさでも同じ手順）

大きさ S ピクセルの正方形に、ピクセルごとの「覆う割合」を計算して描く（輪郭をなめらかにするため）。ピクセル (x, y) の中心は (x + 0.5, y + 0.5)。中心 c = (0.5S, 0.5S)。d を「形のふちまでの距離（ピクセル。内側が負）」とすると、覆う割合は clamp(0.5 − d, 0, 1)。

| 部品 | 形（S に対する割合） | d |
|---|---|---|
| 輪 | 中心線の半径 0.34S、太さ 0.16S | \|r − 0.34S\| − 0.08S（r は c からの距離） |
| 点 | 半径 0.13S | r − 0.13S |
| 輪の欠け（待機中） | 輪の 315°（右から時計回り。右上）を中心に 90° を抜く | 輪の覆う割合に clamp(0.5 + e, 0, 1) を掛ける。e は、そのピクセルの角度から欠けた所の端までの角度（ラジアン）× 0.34S |
| 右上の点（異常） | 中心 (0.76S, 0.24S)、半径 0.22S。まわり 0.07S を透明にして、輪と離す | 点の中心までの距離 − 0.22S |

- 「透明にする」は、輪と点の覆う割合に (1 − 半径 0.29S の円の覆う割合) を掛けること。右上の点はその上に重ねる（アルファの合成）。
- 色は 1 色。アルファは前もって掛けない値で持つ。
- 手順を JavaScript で書いたものが `mock/glyph.js`。`icons/tray-{ok,wait,fault}-{16,20,24,32}.png` と `icons/toast-{fault,ok}-96.png` は、その出力（`node docs/design/ui/mock/export.js` で書き出す。Rust で描いたものと見比べる用）。
- 大きさ: Windows の小さいアイコンの大きさ（拡大率 100% で 16、125% で 20、150% で 24、200% で 32）で描く。拡大率を取れなければ 32 で描いて、Windows に縮めさせる（少しぼやける）。

### 4.3 マウスを乗せたときの 1 行とメニュー

設計（7.4 のトレイ）の決まりで、次の形にする。

| 場合 | 1 行 |
|---|---|
| ふつう | `{全体}　{a}/{b}`（a は正常の台数、b は未接続でない台数）。例: `正常 3/3`、`待機中 2/3` |
| 異常 | `異常：{最も優先度の高い案内の見出し}`。例: `異常：トラッキングが始まりません` |
| 仕組みの側の不具合、VIVE Hub が止まっているとき | `待機中：{ステータスパネルの 1 行}`。例: `待機中：VIVE Hubを起動してください` |
| 追いつき、起動の途中（1 行なし） | `待機中` |

- 「：」は全角。見出しと 1 行は「|」と「\n」を除いて 1 行にする。Windows は 127 文字で切るので、越えたら 126 文字と `…` にする。
- メニュー（右クリック）: `OpenUTを開く`、区切り、`終了`。左クリックでもメインウィンドウを開く（設計の 7.4）。

| まとめた案内 | 見出しのうしろに `（ほか{n}件）` を 1 つの語句として足す（設計の 7.1） |

- `SetOverlayRaw` は、`openvr.h` の説明に「送れるデータの量に上限がある」とある（値は書かれていない）。1280 × 492 の RGBA は約 2.5 MB、最も高い 1280 × 666 は約 3.4 MB。失敗したとき（戻り値か `VREvent_ImageFailed`）は、すべての寸法を半分（幅 640、字 32 と 27）にして描き直す。M1-12 の試作で、1280 が通るかを確かめる。

### 5.4 折り返しの手順（オーバーレイとメインウィンドウで同じ）

文言の関数は行ごとに、切ってよい場所で分けた語句の並びを返す（1.3、3 章）。行（「。」で分けたもの）ごとに、次のとおり詰める。

1. いまの行に次の語句を足しても幅に収まるなら、足す。
2. 収まらず、その語句が 1 行の幅に収まるなら、いまの行を確定して（空なら確定しない）、次の行をその語句から始める。
3. 1 つの語句だけで 1 行の幅を超えるとき（末尾の長い呼び名の `（…{末尾}）の` など）は、いまの行を確定せずに、その語句を 1 文字ずつ続けて詰め、行がいっぱいになったら折り返す。次の 2 つを守る。
   - 行の先頭に `、。，．）」』ー…` と小さい仮名（`ぁぃぅぇぉっゃゅょゎァィゥェォッャュョヮ`）が来ないように、前の行の終わりの文字を次の行へ送る。
   - シリアル番号に使える文字（ASCII の英数字と `-`。設計の 4.4）の続きは、続き全体が 1 行に収まるなら途中で切らず、続きの初めから次の行へ送る。1 行に収まらない続き（末尾が長いとき）は、行がいっぱいになったところで切る。どの行も幅を超えない。

例（オーバーレイ。末尾が 32 文字の呼び名）: `トラッカー1（…A7KWM3X9QH2VT8ND4` / `ZR6BY0PC5FJ0001）の電源だけを` / `入れ直してください。` / `ほかのトラッカーとドングルは、` / `そのままにしてください`（`vr-serial32.png`）。

幅は、オーバーレイが 1044 ピクセル（見出しとすることで同じ）、メインウィンドウのステータスパネルと案内の一覧が 2.3 の幅。ウィンドウの幅を変えたら、そのときの幅で計算し直す。手順を JavaScript で書いたものが `mock/wrap.js` の `wrap`（モックアップの文字は、これで折り返している）。表のシリアル番号とファームウェアのバージョンは文の中の語句ではないので、この手順を使わず、2.5 の形で分ける。
