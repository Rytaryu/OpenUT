# 設計の初版（概要）

2026-11-27 の調査から起こした骨組み。実装できる粒度にするのは設計担当の仕事（`docs/project/STATUS.md` の 3）。

## VIVE Hub の構成（解析メモによる）

ドングル（HID）とトラッカーを、`ViveTrackerServer.exe` が受け持つ。SteamVR のドライバー、設定画面、VIVE Hub 本体は、名前付きパイプでこのサーバーと話す。出典は `docs/research/findings-2026-11-27.md` の「先行事例」。

## 段階1: 見張り役

### ログの行と状態

| ログの行 | 意味 |
|---|---|
| `Add new tracker: (N)` / `Remove tracker (N)` | 接続 / 切断 |
| `Tracker (N) - switch to HOST mode.` | N をホストにする命令 |
| `Got host wifi info.` | PC がホストの Wi-Fi 情報を持った |
| `Assign wifi info to client tracker (index: N).` | クライアント N に渡した |
| `Wifi info is not yet available.` | 尋ねられたが渡せない（不具合の印） |
| `Client tracker (index: N) is connected to host: 1` | ホストの Wi-Fi につながった（0 は切れた） |
| `map state: 2` / `map status: 6` | 地図の同期済み / 地図の再利用に成功 |
| `Pose data - status: 2` / `3` / `4` | 追跡中 / 喪失 / 直前に喪失 |
| `OET LOST TRACKING!` / `OET reloc back.` / `OET OVERSPEED!` | 喪失 / 復帰 / 速度の異常 |

行の先頭は `[YYYY-MM-DD hh:mm:ss.mmm +9 0x.... LEVEL 関数名] [スレッド番号] 本文` の形。番号の意味は、解析ライブラリ pyvut の定数の名前（`POSE_OK`、`MAP_REUSE_OK` など）と合う。

### 検出の規則

| 規則 | 条件 | 案内 |
|---|---|---|
| R1 Wi-Fi 情報なし | ホストへの命令のあと `Got host wifi info.` がないまま、`Wifi info is not yet available.` が 3 回続く | ホストの電源だけ入れ直す。リセットは不要 |
| R2 地図同期が遅い | ホストの Wi-Fi につながって 30 秒たっても `map state: 2` にならない | トラッカーをホストの近くに置く |
| R3 ホストが位置を出せない | ホストが 30 秒以上 status 3 か 4 | ホストに部屋を見せる |
| R4 切断 | 操作と関係のない `Remove tracker` | 切れたことを知らせる |

しきい値（3 回、30 秒）は仮の値。再生テストで決め直す。

### 部品

- **読み取り**: ファイルの追記を追う。日付の切り替わりで次のファイルへ移る。行を構造化した記録にする。
- **状態**: 記録を受けて、トラッカーごとの状態を進める。入出力を持たない。
- **規則**: 状態と時刻から、案内を出すかを決める。入出力を持たない。
- **通知**: SteamVR の通知と、デスクトップの通知。
- **集計**: 日ごとの数字をファイルに書く。

ログは数秒おきにまとめて書き出されるので、検出はその分遅れる。

## 段階2: 置き換えランタイム

| 部品 | 役割 |
|---|---|
| ドングル層 | HID でドングルと話す。接続と切断の検出、状態と姿勢の受信、トラッカーへの指示の送信 |
| 調停役 | ホストの選択、Wi-Fi 情報の保持と配布、地図同期の監視、行き詰まりからの復旧 |
| 姿勢フィルタ | 速度の異常と 1 m を超える飛びを落とす。喪失中は最後の姿勢を保ち、追跡外として報告する |
| OpenVR ドライバー | SteamVR にトラッカーとして登録する |
| 較正 | HMD の空間との位置合わせを自前のファイルに保存する |
| 状態表示 | 段階1 の見張り役を使う。入力をログから調停役の出来事に差し替える |

調停役の決まり: ホストの Wi-Fi 情報は、ホストが替わるまで消さない。クライアントに尋ねられて持っていなければ、ホストに問い合わせる。VIVE Hub で起きた不具合は、この 2 つが守られていないことで起きている。

起動時に `ViveTrackerServer.exe` が動いていたら、起動を断る。ドングルは同時に 1 つのプログラムしか扱えない前提。
